# 字幕与新音轨的验收指标

> 与 [CONVERT-QUALITY-METRICS-zh.md](CONVERT-QUALITY-METRICS-zh.md) 配套：那份管画面，这份管文字和声音。
> 基线取自 2026-10-27 的配音成品 `tears_of_steel_zh_20mb_v3.mp4`（734 s / 71 句 / 720×300）。
> 复现脚本见 §3，全部数据从 job 目录算出来，不依赖截图。

## 0 判定口径

字幕回答「看得清、跟得上」，音轨回答「听得懂、听着不别扭」。两者共用一个次序：
**先查「有没有」，再查「好不好」**——缺一句、静音一句、字幕和声音说的是两句话，
任何一项都比「不够自然」严重一个量级。所以下面每节都是 P0/P1/P2 三层，P0 挂一条即判不可用。

## 1 字幕

### 1.1 P0 完整性与一致性

| # | 指标 | 门槛 | 基线（2026-10-27 重测） | 来源 |
|---|---|---|---|---|
| 1 | 覆盖 | 有对白的 cue 都有译文；缺译**整条删除**，不得回落成原文（否则中英混排） | 71/71（#60 整条删，保留原声） | `subtitles.ass` × `fit_auto.json` |
| 2 | **字幕文本 ≡ 配音文本** | 逐字相同 | ✅ **0/71** | `audit_translation.py` |
| 3 | 专名一致 | 同一角色全片一种写法 | ✅ 屏上 0 处漂移 | `audit_translation.py` |
| 4 | 时间轴不重叠 | 0 处重叠 | ✅ 0 | `audit_subtitles.py` |
| 5 | 起点对齐配音 | ≤ 50 ms | ✅ 0.00 s（字幕起点就是配音响起点） | 同源生成 |
| 6 | 存在字幕轨 | 容器内有 subtitle 流 | ✅ `mov_text`，`language=chi` | `ffprobe -select_streams s` |
| 7 | 单语/双语模式 | Translation 只出一条；Dual 出两条 | 已实现（`SingleLanguageAss()`） | commit `8b12a63` |

第 2、3 项在 2026-10-27 之前分别是 13/71 和 3 处，第 6 项是 0 流——详见 §1.4。

### 1.2 P1 可读性

| 指标 | 门槛 | 旧基线（源 cue 时间轴） | 新基线（配音时间轴） |
|---|---|---|---|
| 阅读速度 | ≤ 9 字/秒（硬上限 12） | p50 4.8、p95 13.0、max **26.3**；>9 有 12 条 | ✅ p50 **4.7**、p95 **6.8**、max **7.7**；>9 有 **0** 条 |
| 单行宽度 | ≤ 32 单位（16 汉字，CJK 记 2） | max **42 u**；>32 有 7 条 | ✅ max **32 u**；>32 有 **0** 行 |
| 最短停留 | ≥ 0.8 s | 17 条 < 0.8 s，最短 0.30 s | ⚠️ **7 条** < 0.8 s，最短 0.26 s |
| 空白间隔 | ≥ 0.08 s（防闪烁） | 21 处 < 0.08 s | ⚠️ **10 处** < 0.08 s |
| 重叠 | 0 处 | 0 | ✅ 0 |

旧基线的问题不是译文长，是**源 cue 太短**——英文 0.4 s 说完一句，字幕沿用了源时间轴，
#59 因此在 0.38 s 里放「你把我遗忘在地球上！」= 26.3 字/秒。

新基线改用**配音自己的时间轴**（`anchor` → `anchor + seconds`），于是同一句话有了它
实际被说出的那几秒，阅读速度自然落到 7.7 字/秒以下。停留时长还有 7 条不足，是因为
这七处的**下一个说话人抢先开口**，字幕必须让位；重叠是绝对不能犯的那一类，
短是可以接受的。想再压，只能合并相邻 cue（把两句并成一条字幕），那是另一个改动。

### 1.4 字幕与配音同源（问题与修法）

修好之前有 13 处不一致，分两类，这里留作记录：

**A 译名漂移（3 处）** — `#2 #43 #49`

```
字幕: 听着，凯莉，我们必须追求自己的兴趣。
配音: 听着，塞莉亚，我们必须追求自己的兴趣。
```

Celia 在字幕里 3 次写作「凯莉」、1 次写作「塞莉亚」，配音里 4 次全是「塞莉亚」。
F0 修完之后配音是对的，字幕停在旧译名上。

**B fit 阶段的重写没有回写（10 处）**

| 行 | 字幕（`zh_final.json`） | 配音（`fit_auto.json`） |
|---|---|---|
| #3 / #44 | 我和你的机器人，我只是想在太空中成为最棒的人。 | 你有你的机器人，我只想在太空闪耀。 |
| #50 | 以及一个。 | 而且还是个混蛋。 |
| #52 | 她为什么这样做？ | 为啥？ |
| #55 | 天啊！ | 我靠！ |
| #25 | 出发，出发，出发。 | 走走走！ |

根因是**两条链路各取一个数据源**：字幕读 `zh_final.json`，配音读 `fit_auto.json.text`，
而 fit 阶段的覆盖表（`zh_overrides.json`）和 budget 重写只改了后者。更糟的是**根本没有
字幕文件**——观众一个字都看不到，所以这个问题谁也发现不了。

**修法（2026-10-27，`tools/dubbing/subtitles.py`）**：fit 阶段跑完直接用手上的行写出
`subtitles.ass`，`dub.py` 封装时 `-map 2:s:0` 进容器。文本取 `text`（引擎念的那句），
时间取 `anchor` → `anchor + seconds`（实际被说出并被 tempo 压缩后的那段）。

于是「一致」不再是一条要检查的断言，而是**文件里不存在第二个可以不一致的字段**。
`audit_translation.py` 仍逐条比对，作为「接线被改坏」的哨兵：现在恒为 0/71。

同时落地两条生成期约束（不是事后检查）：
- 停留时长 ≥ 0.8 s，除非下一位说话人抢先开口——**让位优先于时长**，重叠是绝对不能犯的
- 单行 ≤ 32 单位，超了按标点断行，标点位置离均分点太远就硬切（宁可难看，不可超宽）

容器：mp4/mov 用 `mov_text`（丢样式、保留文本与时间轴），mkv 用 `ass`（样式保留）。
语言标签必须写 **`chi`**——mov 容器只认 ISO 639-2/B 码，写 `zho` 会被静默丢弃。

## 2 新音轨

### 2.1 P0 完整性与对齐

| # | 指标 | 门槛 | 基线 |
|---|---|---|---|
| 1 | 时长拟合 | `ratio = 实际/窗口` ≤ 1.00，0 条超标 | max **1.00**，0 条 |
| 2 | 真截断 | 0 条 | **1 条**：#17 窗口 0.50 s 说了 0.92 s，**切掉 0.42 s** |
| 3 | 起点对齐 | ≤ 50 ms | 0.00 s |
| 4 | **原声已抽走** | 无配音处的 `output - bed` ≈ 0 dB | **−0.36 dB**（干净） |
| 5 | 每句都有声 | 无静音行 | 71/71 |
| 6 | 流不丢 | 视频 + 音频，声道数不变 | 2 流，立体声 |

第 2 项的计数要和 mix 日志分开看：日志写「掐尾 `#17 #54 #55`」，但按 wav 实测只有 #17 真的少了 0.42 s，
#54（0.44 s）和 #55（0.51 s / 加速后 0.36 s）是**撞车挤压**而非截断——相邻两句的窗口都是 0.50 s，
> 前一句超了以后这一句的可用量变短。日志的清单比现实严，验收以 wav 实测为准。

### 2.2 P1 电平

| 指标 | 门槛 | 修复前 | 现在（v5） |
|---|---|---|---|
| 逐句电平离散 | p95−p05 ≤ 3 dB | 2.7 dB（>3 dB 有 4 条） | ✅ **1.5 dB，>3 dB 的 0 条** |
| 母版真峰 | ≤ −1 dBTP | −0.1 dBTP（样本峰 −0.45） | ✅ **−1.9 dBTP**（样本峰 −2.0） |
| 成品过零样点 | 不多于源片 | 12 个（源片 **249** 个） | ✅ **2 个** |
| 整轨响度 | 与原片差 ≤ 3 dB | −14.5 vs −12.0 LUFS | ✅ −14.3 vs −12.0 |
| 动态范围 | LRA 接近源 | 19.8 vs 20.8 LU | ✅ |
| bed 衰减 | 只在该响处压，−3±1 dB | −3.0 dB / 71 处 | ✅ 不变 |

**"真峰"要分两处量，门槛也不一样。** 母版（PCM）必须 ≤ −1 dBTP，这是能守住的门槛，
现在 −1.9。**成品 AAC 解出来的峰守不住**：源片自己的音轨（MP3 191k）解码就有 **249 个样点
越零**、峰值 +1.15 dBFS，母版限到 −2 dBTP 之后写 256k AAC，解码仍是 2 个样点 / +1.25 dBFS。
这不是母版太热，是编码器的过冲：母版改 0.03 dB，同一个位置的解码峰就跳 1.7 dB
（实测 −3 dBTP 的母版反而解出 +0.4）。所以这一项按**过零样点的个数**验收，
不看峰值 dB——249 → 2 是能拿出手的改进，把母版再压低只是拿响度换一个不存在的确定性。

电平离散原来 2.7 dB 的根因不是"全片中位数"，是**量错了统计量**：mix 用整段 RMS 归一
（包含句尾的静音），审计脚本用 20 ms 块的 75 分位（也就是"说话的音量"）。
一条尾巴长的句子在 RMS 眼里"很轻"，于是被推高，实测就高出 3~4.9 dB。
两者对齐之后（mix 也用 75 分位）离散降到 **1.5 dB**。

> 顺带否掉一个想法：把目标换成"同一场内的中位数"实测更差（6.1 dB vs 2.7）。
> 逐句电平的差异是**合成器的**，不是**场景的**，场内取中位数只是给每场加了一个随机偏移。
> 详见 §6 第 8 条。

|---|---|---|
| atempo 使用率 | ≤ 20% | 6/71 = **8.5%**，最高 **1.40** |

### 2.4 P0 音色对准（新增）

**症状**：画面是男人，出来是女声；或者一个人明显不是这个嗓子。
**为什么以前没抓到**：`voice.py` 的基频否决只能证明一句"是男声"，它区分不了两个男人，
而且按"轮"生效——一轮里只要有一句读成女声，整轮就不改；下游再没有任何一处复核。
合成器是完全听话的，标签错它就照着错。

三个读数，同一把尺（`tools/dub-metrics/pitch.py`，YIN，10 ms 帧）：

| 读数 | 从哪来 | 说明 |
|---|---|---|
| 画面（screen） | 源句从人声分轨里切出来 | 观众看到的那张嘴 |
| 选用（chosen） | 该标签的参考音（`refs_auto/<speaker>.wav`） | 流水线打算用的嗓子 |
| 交付（delivered） | `dub_auto/zhNN.wav` | 观众听到的 |

按顺序比，就能把错分到工序上：

| 指标 | 门槛 | 基线（2026-10-27，v5） |
|---|---|---|
| **heard**：交付 vs 画面，≥7 半音即错 | 0 条 | ❌ **6/25 可测**（24%），其中 **4 条是男女互串** |
| **label**：选用 vs 画面，≥7 半音 | 0 条 | ❌ **6/25**（同 6 条，即错在分轨） |
| **voice**：交付 vs 自己的参考音，≥7 半音 | 0 条 | ❌ **2/69**（#27 `Come on.` 高 8.2 半音、#55 `Fuck!` 高 11.1 半音） |

7 半音是 1.5 倍音高，同一个人的两次演绎进不了这个距离；换人或换性别一定超过。
参考音实测 celia 211 / tom 153 / robot 132 Hz，男女带按 165 / 195 Hz 划分。

三条落地结论：

1. **这不是合成器的错，是配音的错。** `voice`（交付 vs 参考音）只有 2 条，`label`
   （参考音 vs 画面）6 条——合成器忠实复现了给它的参考音，错在上游选嗓子。
2. **根因是全片只有 3 个嗓子，至少 4 个人在说话。** 白发老人（131 s）和人声分轨里
   90–110 Hz 的句子被归到 `tom`，而 `tom` 的参考音是 153 Hz 的年轻人；同一条
   「tom」里画面音高成两簇（~100 Hz 与 ~220 Hz），差一个八度。分轨器只找到
   tom/celia/robot 三个簇，把老人并进了年轻人。
3. **判定要求源句干净**：只有"人声比伴奏高 9 dB、且伴奏绝对电平 < 0.03"的帧才计入
   （25/72 句可测）。剩下的 47 句不是没问题，是**量不出来**——人声分轨里留了大量音乐，
   一个稳定的 pad 在 YIN 里也是一条合格的基频。宁可少判，不可错判。

**别用 Praat 的 `to_pitch_ac` 做这件事**：它把男声主音报成 233 Hz（二倍频），
因为自相关锁二次谐波和锁基频一样容易，锁哪个取决于那一帧有多响。同一句源录音和合成音
的倍频率还不一样，用它做阈值判断等于在比两个不同的尺子。

### 2.5 P0 口型有声（新增）

**症状**：嘴在动，没有声音。**为什么以前没抓到**：拟合器只能加速、不能放慢，
译文比英文短的时候中文读完就停了，剩下的人在动嘴；而原声已经被分离拿走，
那里就只剩伴奏。旧的「时长拟合 ratio ≤ 1.00」只看有没有超，不看有没有填满。

| 指标 | 门槛 | 基线（v5） |
|---|---|---|
| 有中文覆盖的语音占比 | ≥ 99% | ❌ **70.1 / 100.7 s = 69.7%** |
| 单句空洞 ≥ 0.25 s | 0 条 | ❌ **31 条** / 71 |
| 最大空洞 | 0 | ❌ **3.43 s**（#38 @258.66 s） |
| 起点晚于语音 > 0.25 s | 0 | ✅ 0 条（每句都压在语音起点上） |
| 尾巴超出语音 > 0.25 s | 0 | ⚠️ 18 条（最多 #16 +1.51 s） |

最坏的 8 条：

| # | 位置 | 语音 | 中文覆盖 | 空洞 |
|---|---|---|---|---|
| #38 | 258.66 s | 4.16 s | 0.73 s | **3.43 s** |
| #68 | 525.86 s | 4.16 s | 1.06 s | 3.10 s |
| #43 | 316.04 s | 3.28 s | 0.76 s | 2.52 s |
| #44 | 322.28 s | 2.28 s | 0.46 s | 1.82 s |
| #70 | 559.18 s | 1.88 s | 0.34 s | 1.54 s |
| #4 | 30.52 s | 3.94 s | 2.50 s | 1.44 s |
| #0 | 2.36 s | 4.04 s | 2.66 s | 1.38 s |
| #64 | 429.00 s | 1.60 s | 0.52 s | 1.08 s |

**在中轴上核过**：把母版和伴奏在空洞处逐段比电平，#38/#68/#43/#44/#70 的交付电平
分别是伴奏 **−0.6 / −0.4 / −0.4 / −0.1 / −0.3 dB**，也就是那里放的就是音乐，
不是压低了的人声。319.6 s 的画面是男生张嘴说话、音轨只剩环境声，可直接对照。

两条口径要说清：

- **语音按 `step1_align` 同一套规则切**（逐句相对门限 12%、0.35 s 内断句不断），
  再加一道绝对电平闸：低于全片中位数句 10 dB 的段不算语音。258 s 那段是一句气声，
  分轨里只剩 −27 dBFS 的底噪，不加闸会把"安静的镜头"算成"没配音"。
- **中文侧用的是 `mix_auto.json` 的 `anchor/seconds`**，和混音器实际写进母版的区间一致，
  不是从成品反推，也不是从字幕反推。

## 3 怎么测

脚本在 `tools/dub-metrics/`，都只读 job 目录（`$DUB_JOB`，默认 `F:/tmp/s2st/jobs/t5`）：

```bash
PY=/c/Users/Administrator/.workbuddy/binaries/python/envs/default/Scripts/python.exe
DUB_JOB=<job目录> $PY tools/dub-metrics/measure_subtitles_voice.py     # 字幕可读性 + 拟合/合成电平
DUB_JOB=<job目录> $PY tools/dub-metrics/measure_delivered_levels.py    # 交付电平（含 mix gain）、重叠、原声残留
DUB_JOB=<job目录> $PY tools/dub-metrics/measure_truncation_and_residue.py  # 活跃帧电平、截断明细、bed 对照
DUB_JOB=<job目录> $PY tools/dub-metrics/audit_voice_identity.py        # 音色对准，错一处退 1
DUB_JOB=<job目录> $PY tools/dub-metrics/audit_coverage.py              # 口型有声，留一个洞退 1
```

`audit_voice_identity.py` 和 `audit_coverage.py` 是**闸门**（退出码非 0 即不合格），
前三个是读数。共用的两件事拆了出去：`wavio.py` 读 wav（16/24/32 位），
`pitch.py` 测基频（YIN，纯 numpy，不用 praat）。

`audit_coverage.py` 会顺手核对：把最坏的几个空洞在**母版**上和伴奏逐段比电平，
报 `master is -0.4 dB over the bed -> silent`。这一句比任何表格都有说服力——
它证明的不是"算法认为没声音"，而是"成品里那里确实只有音乐"。

这些脚本原先只活在 `F:/tmp`（不是 git 仓库），和配音链 33 个脚本一样随时会没；
入库的原因不是"以后可能用到"，而是**这套数字每次发版都要重测一遍**，
差 3 dB 听不出来、26 字/秒肉眼只觉得"有点快"，只能靠脚本。

单条命令版本：

```bash
# 整轨响度与真峰
ffmpeg -i out.mp4 -map 0:a -af ebur128=peak=true -f null - 2>&1 | grep -E "I:|Peak:"
# 配音处 vs 无配音处的电平差（原声残留）
#   见脚本 §2，需要 stems_out/{vocals,no_vocals}.wav 与混音成品同时读取
# 字幕阅读速度
#   len(zh) / (cue.end - cue.start)  > 9 即超速
```

**别用截图或肉眼判断这四项**：电平差 3 dB 听不出来但会被审片打回，
字幕 26 字/秒肉眼也只觉得"有点快"。

## 4 基线汇总（2026-10-27 重跑，带字幕轨）

| 层 | 通过 | 不通过 |
|---|---|---|
| 字幕 P0 | 覆盖 71/71、**字幕≡配音 0/71**、屏上译名 0 漂移、重叠 0、起点误差 0、有 `mov_text` 轨 | — |
| 字幕 P1 | 阅读速度 max 7.7 字/秒（0 条 >9）、行宽 max 32（0 行超）、间隔 <0.08 s 仅 10 处 | <0.8 s 有 7 条（下一位说话人抢先开口，让位优先） |
| 字幕 P2 | 画布、PSNR 56–60 dB、零渲染开销 | — |
| 音轨 P0 | 拟合 0 超标、对齐 0 ms、原声残留 −0.36 dB、71/71 有声 | 截断 1~4 条（每轮不同，见下）；**音色 6/25 句错**（§2.4）；**30.5 s 语音没被中文覆盖**（§2.5） |
| 音轨 P1 | 离散 1.5 dB、响度 −14.3 LUFS、bed −3.0 dB、母版 −1.9 dBTP、成品过零 2 个（源片 249） | — |
| 音轨 P2 | atempo 8.5% | 尾静音 max 460 ms |

⚠️ **"截断"条数每轮不同**（实测 1 / 2 / 3 / 4 条都出现过）：TTS 是 `--temp 0.7` 随机采样，
同一个窗口这一轮放得下、下一轮放不下。所以这个数字只能读作"量级"，不能当验收线；
当验收线用的话，要么固定 seed（牺牲自然度），要么按多轮的最差值定阈值。

## 5 缺口

1. ~~**配音成品没有字幕轨**。~~ 已解决：`subtitles.ass` 由 fit 阶段生成并在封装时
   `-map 2:s:0`，`mov_text` + `language=chi`。剩下的选择是**软字幕还是烧录**——
   目前是软字幕（可关、可换轨），烧录需要一条 `ass` 滤镜，那是另一个交付形态。
2. **没有可懂度/自然度的客观指标**。MOS 要人听；机器代理（STOI 需要参考信号，本场景没有）也没接。
3. **说话人相似度只能否决，不能打分**。ECAPA 在短句上退化到 0.03–0.17，只能靠基频单边否决，
   所以"这句像不像 Celia"目前无法量化。跨语言更差：合成音的中文片段与同一角色的英文参考音，
   余弦差的中位数只有 0.09、p05 已经翻负（−0.09），直接拿它做判定会报出 14/69 条"像别人"，
   而同一批句子用基频只报 2 条——所以 §2.4 用基频，不用嵌入。
4. **全片只有 3 个嗓子，至少 4 个人在说话**。`step1_align` 的聚类只分出 tom/celia/robot，
   白发老人（131 s 起）与年轻男主都在 `tom` 里，画面音高差一个八度（~100 vs ~220 Hz）。
   这是 §2.4 那 6 条里的多数。要修得让聚类能拆出第 3、第 4 个男声（提高簇数上限，
   或按场景内 F0 分位二次聚类），而不是继续让基频否决兜底。
5. **拟合器只能加速，不能放慢**。`step12` 的 tempo 上限 1.35，下限 1.0——译文更短时它
   什么都不做，中文读完就停，这就是 §2.5 那 30.5 s 的直接来源。最小改动是放开下限
   （atempo 0.85 以内基本听不出变慢），每句按 `speech/seconds` 算出应有的 tempo。
6. **分离质量没有量化**。`no_vocals.wav` 里到底残留多少原人声，只有 −0.00 dB 这一个
   全片聚合值；应该按段统计（音乐段 vs 对白段）。
   ⚠️ 这个数被 24-bit 母版坑过一次：审计脚本原来按 16-bit 硬解，读 24-bit 母版得到的是噪声，
   报出"原声回来 +12.9 dB"。现在 `read_wav` 走 soundfile，任何位深都对。
7. **语速比未测**。中文字/秒 与原句英文音节/秒 的比值是"译得是否啰嗦"最直接的指标，
   今天只有 ratio（时长/窗口）这一个间接量。
8. **成品 AAC 的过冲没有确定性解法**。母版可以确定地压到 −2 dBTP，解码后那 1~2 dB 的过冲
   随编码器状态跳（母版 0.03 dB 的差别就能让峰值跳 1.7 dB）。要彻底消掉只能换无损交付
   （mkv + flac），或者给 AAC 单独做一次"编码后测、超了再降"的闭环，成本高、收益是 2 个样点。

## 6 提升准确性的杠杆（按实测收益排序）

「准确」在这条链上有四种含义，混在一起谈会互相抵消：**时间准**（声音落在该落的地方）、
**话准**（说的是原文的意思）、**人准**（是那个人在说）、**电平准**（响度不失衡）。
下表按「每改一处能消掉多少条已测缺陷」排序，成本指要不要重新合成（约 7 分钟 / 71 句）。

| # | 杠杆 | 消掉什么（实测） | 成本 | 状态 |
|---|---|---|---|---|
| 1 | **字幕与配音共用一份文本** | 13/71 不一致、#52 语义被换 | 零 | ✅ 已做，现 0/71 |
| 2 | **术语表（人名/专名）** | 3 处「凯莉」、译名漂移 | 零 | ✅ 已做，现 0 处 |
| 3 | **合成前可行性预检** | 省掉必然放不下的那一次合成 | 零 | ✅ 已做，本片拦下 2 句 |
| 4 | **cue 尾部按真实语音重定界** | 每句白丢 0.11~0.19 s（cue end 中位早于真实语音） | 中 | 待做 |
| 5 | **相邻短句合并成一个窗口** | #54/#55 撞车（两句都只有 0.50 s 窗口） | 中 | 待做 |
| 6 | **TTS 多采样、按音色+时长选优** | 短句音色漂、#59 +4.9 dB | 高（N 倍合成） | 待做 |
| 7 | **混音出口 limiter** | 成品过零 12 → 2 个；母版 −1.9 dBTP | 低 | ✅ 已做 |

| 12 | **分轨聚类拆出第 3/4 个男声** | §2.4 那 6 条里多数（白发老人被归进年轻人） | 高（改聚类 + 重跑全链） | 待做 |

前三条是**零成本且不需要重新合成**的，就该先做。

### 6.1 时间准：先量上游，再谈让步

实测 cue 边界与干声里真实语音的关系：起点中位 **+0.02~0.04 s**（准），
终点中位 **−0.11~−0.19 s**（cue 在真实语音结束前就收了，两种切分口径给出的区间）。
每句白丢 0.1~0.2 s，71 句合计 8~13 s——这不是"借"，是把本来就属于自己的时间要回来。
修法是拿 `vocals.wav` 做 VAD 重定界，而不是继续在 fit 里加大 `EXTEND`。

> 口径说明：`vocals.wav` 是分离出来的干声，音乐段落里仍有残留（204 个"语音段"，
> 门限 −42 dBFS），所以**绝对覆盖率不可全信**（测得"cue 时间里有 22.8% 没人说话"偏大）。
> 可靠的是**符号与量级**：起点准、终点系统性偏早，这一点在两种切分方式下一致。

窗口本身已经是「到下一句开始」的最大可用量（`usable_window`：`next_start − start − 0.05`，
帽在 `end − start + 1.5`），所以 #17 的 0.50 s 就是物理上限，**没有可借的空白**——
它需要的不是更好听的加速，是一句更短的话。24 条 cue 后面不足 0.15 s，只能靠合并。

### 6.2 话准：三道闸

1. **硬校验（已实现，`tools/dub-metrics/audit_translation.py`）**：数字、否定、疑问、专名四条正则规则。
   对 71 句跑出 1 条真问题（#29「Nothing to worry about.」→「一切都好。」丢了否定）
   + 3 条译名，其余干净——说明**翻译模型本身没大问题，问题在链路和术语**。
2. **术语表**：把人名/专名写进一次 prompt + 事后替换双保险。Celia 三种写法就是没表的代价。
3. **回译校验**：只对「被 budget 重写过的句子」做（本轮 5 条），回译后与原文算相似度，
   低于阈值就换一版。全量做成本翻倍，不必要。

**不要**用「字数比」当质量指标：`#50 And a dick.` 译成「以及一个。」字数不少，意思全丢；
译成「而且还是个混蛋。」字数更多但正确。长度只能判「塞不塞得下」，判不了「对不对」。

### 6.3 人准：短句是唯一的战场

说话人判定在长句上没问题（ECAPA + 0.15 margin），崩的全是 0.4–1.0 s 的感叹句——
这正是 4:00 男声变女声的根因，现有修法只是**单边否决**（基频证明是男声），
所以它能把错的行改对，但**不能给出"这句像不像 Celia"的分数**。

可做且不需要新依赖的两件事：
- **用同场长句的音频做参考**：短感叹句不要单独选参考，直接借同一个人在同一场的长句片段，
  音色一致性立刻上来；
- **多采样按复合指标选**：`--temp 0.7` 每次不同，生成 2~3 个候选后按
  ①时长是否落在窗口 ②基频轮廓与参考的相关系数 排序。第二条用已经在用的 parselmouth 就能算。

### 6.4 电平准：两个数字就够

- **量你判的那个量。** mix 原来按整段 RMS 归一，审计按 20 ms 块的 75 分位判分；
  尾巴长的句子在 RMS 眼里很轻，于是被推高，实测高出 3~4.9 dB。归一改成同一个 75 分位，
  离散 2.7 → **1.5 dB**，>3 dB 的从 4 条降到 0 条。`gain` 仍夹 ±12 dB。
- **「场内中位数」是错的方向**（已试并否掉）：逐句电平的差异来自合成器，不来自场景，
  场内取中位数等于给每场加一个 0~4 dB 的随机偏移，离散反升到 6.1 dB。
  电平要的是"每句一样响"，不是"每场各自一样响"。
- **出口限幅**（`alimiter=limit=0.794`，4× 过采样后限、再降回 44.1k，`latency=true` 保证 0 采样时移）：
  母版 −1.9 dBTP，成品 256k AAC 解码 2 个过零样点。**别指望把成品也压到 −1 dBTP 以下**，
  那 1~2 dB 是编码器的过冲，母版动 0.03 dB 它就跳 1.7 dB。验收看**过零样点个数**。
- 单句层面的代价：4 句在增益之后峰值会越过 −2 dBTP（最狠的 #0 越 4.7 dB），
  由 limiter 在局部压掉。想彻底避免就得给每句单独限幅（降 crest factor），
  而不是整体降 gain——后者会把这 4 句的语音电平拉开 2~5 dB，又回到离散问题。
