# 字幕与新音轨的验收指标

> 与 [CONVERT-QUALITY-METRICS-zh.md](CONVERT-QUALITY-METRICS-zh.md) 配套：那份管画面，这份管文字和声音。
> 基线取自 2026-10-27 的配音成品 `tears_of_steel_zh_20mb_v3.mp4`（734 s / 71 句 / 720×300）。
> 复现脚本见 §3，全部数据从 job 目录算出来，不依赖截图。

## 0 判定口径

字幕回答「看得清、跟得上」，音轨回答「听得懂、听着不别扭」。两者共用一个次序：
**先查「有没有」，再查「好不好」**——缺一句、静音一句、字幕和声音说的是两句话，
任何一项都比「不够自然」严重一个量级。所以下面每节都是 P0/P1/P2 三层，P0 挂一条即判不可用。

## 1 字幕

### 1.1 P0 完整性与一致性

| # | 指标 | 门槛 | 基线 | 来源 |
|---|---|---|---|---|
| 1 | 覆盖 | 有对白的 cue 都有译文；缺译**整条删除**，不得回落成原文（否则中英混排） | 71/72（#60 整条删） | `lines.json` × `zh_final.json` |
| 2 | **字幕文本 ≡ 配音文本** | 逐字相同 | ❌ **13/71 不同（18%）** | §1.4 |
| 3 | 专名一致 | 同一角色全片一种写法 | ❌ Celia = 「塞莉亚」×4 /「凯莉」×3 | §1.4 |
| 4 | 时间轴不重叠 | 0 处重叠 | 0 | `start[i+1] - end[i]` |
| 5 | 起点对齐配音 | ≤ 50 ms | **0.00 s**（全 71 句） | `fit.start - line.start` |
| 6 | 单语/双语模式 | Translation 只出一条；Dual 出两条 | 已实现（`SingleLanguageAss()`） | commit `8b12a63` |

第 2、3 项是这次新测出来的，之前完全没查过。

### 1.2 P1 可读性

| 指标 | 门槛 | 基线 | 结论 |
|---|---|---|---|
| 阅读速度 | ≤ 9 字/秒（硬上限 12） | p50 **4.8**、p95 **13.0**、max **26.3**；>9 有 12 条（17%）、>12 有 6 条（8%） | ❌ |
| 单行宽度 | ≤ 32 单位（16 汉字，CJK 记 2） | max **42 u**；>32 有 7 条 | ❌ |
| 最短停留 | ≥ 0.8 s（低于此应合并或延长） | 17 条 < 0.8 s，最短 **0.30 s** | ❌ |
| 空白间隔 | ≥ 0.08 s（防闪烁） | 21 处 < 0.08 s | ❌ |
| 字幕停留 / 配音时长 | ≤ 1.5× 且差 ≤ 1 s | 16 条差 > 1 s（#43 字幕 6.24 s / 配音 2.90 s） | ❌ |

最快的一条是 #59：0.38 s 的窗口里放「你把我遗忘在地球上！」= **26.3 字/秒**，没有人跟得上。

四项一起不过，根因不是翻译，是**源 cue 本身就短**——英文 0.4 s 就能说完一句，
字幕沿用了源时间轴。所以修这一档不能只改译文，要么合并相邻 cue、要么给短 cue 加下限、
要么让配音把时间轴撑开（配音侧已经有 `OVERLAP`/`EXTEND` 的机制，字幕侧还没有对应物）。

### 1.3 P2 版面与渲染

| 指标 | 门槛 | 基线 |
|---|---|---|
| 画布 | 窗口宽 ÷ 源宽高比；同宽高比字号逐项相同 | 已实现 |
| 覆盖层 vs 烧录等价性 | PSNR ≥ 45 dB | **56–60 dB** |

### 1.4 字幕和配音说的是两句话（本轮实测）

13 处不一致，分两类：

**A 译名漂移（3 处）** — `#2 #43 #49`

```
字幕: 听着，凯莉，我们必须追求自己的兴趣。
配音: 听着，塞莉亚，我们必须追求自己的兴趣。
```

Celia 在字幕里 3 次写作「凯莉」、1 次写作「塞莉亚」，配音里 4 次全是「塞莉亚」。
F0 修完之后配音是对的，字幕停在旧译名上。

**B fit 阶段的重写没有回写（10 处）**

| 行 | 字幕（`zh_final.json`） | 配音（`fit_auto.json`） |
|---|---|---|
| #3 / #44 | 我和你的机器人，我只是想在太空中成为最棒的人。 | 你有你的机器人，我只想在太空闪耀。 |
| #50 | 以及一个。 | 而且还是个混蛋。 |
| #52 | 她为什么这样做？ | 为啥？ |
| #55 | 天啊！ | 我靠！ |
| #25 | 出发，出发，出发。 | 走走走！ |

根因是**两条链路各取一个数据源**：字幕读 `zh_final.json`，配音读 `fit_auto.json.text`，
而 fit 阶段的覆盖表（`zh_overrides.json`）和 budget 重写只改了后者。
观众会看到「天啊！」听到「我靠！」，#52 连意思都换了。

改法二选一，别两个都做：
- **以配音为准**：字幕从 `fit_auto.json.text` 取，一句渲染两处（推荐，配音已经过时长验证）；
- **以字幕为准**：fit 结束后把 `text` 回写 `zh_final.json`，但要把被改写的句子列出来给人看。

无论哪种，都要加一条断言：`set(字幕文本) == set(配音文本)`，不等就报错而不是静默。

## 2 新音轨

### 2.1 P0 完整性与对齐

| # | 指标 | 门槛 | 基线 |
|---|---|---|---|
| 1 | 时长拟合 | `ratio = 实际/窗口` ≤ 1.00，0 条超标 | max **1.00**，0 条 |
| 2 | 真截断 | 0 条 | **1 条**：#17 窗口 0.50 s 说了 0.92 s，**切掉 0.42 s** |
| 3 | 起点对齐 | ≤ 50 ms | 0.00 s |
| 4 | **原声已抽走** | 无配音处的 `output - bed` ≈ 0 dB | **−0.36 dB**（干净） |
| 5 | 每句都有声 | 无静音行 | 71/71 |
| 6 | 流不丢 | 视频 + 音频，声道数不变 | 2 流，立体声 |

第 2 项的计数要和 mix 日志分开看：日志写「掐尾 `#17 #54 #55`」，但按 wav 实测只有 #17 真的少了 0.42 s，
#54（0.44 s）和 #55（0.51 s / 加速后 0.36 s）是**撞车挤压**而非截断——相邻两句的窗口都是 0.50 s，
> 前一句超了以后这一句的可用量变短。日志的清单比现实严，验收以 wav 实测为准。

### 2.2 P1 电平

| 指标 | 门槛 | 基线 | 结论 |
|---|---|---|---|
| 逐句电平离散 | p95−p05 ≤ 3 dB | **2.7 dB**（>3 dB 有 4 条，>6 dB 有 1 条：#59 +4.9） | ✅ 边缘 |
| 真峰 | ≤ −1 dBTP | ❌ **+1.9 dBFS**（源片 +1.2） | ❌ |
| 整轨响度 | 与原片差 ≤ 3 dB | −14.5 vs −12.0 LUFS（低 2.5 dB，人声被抽走的正常结果） | ✅ |
| 动态范围 | LRA 接近源 | 19.8 vs 20.8 LU | ✅ |
| bed 衰减 | 只在该响处压，−3±1 dB | −3.0 dB / 71 处 | ✅ |

真峰 +1.9 dBFS 是**继承来的**：源片本身 +1.2。但加进来的人声抬了 0.7 dB，
AAC 解码后过零就削顶——这一条要么在混音出口挂 limiter，要么整体降 2 dB 后回放时补。

长句/短句的电平差是因为 mix 的 `gain = target/level` 被夹在 0.25~4.0（±12 dB）：
#20 要 ×2.71 才够响，#59 只该 ×0.65 却给了 ×1.53。夹取边界不该靠中位数，应该按"同一场内的中位数"。

### 2.3 P2 自然度

| 指标 | 门槛 | 基线 |
|---|---|---|
| atempo 使用率 | ≤ 20% | 6/71 = **8.5%**，最高 **1.40** |
| 首尾静音 | 前 ≤ 40 ms / 后 ≤ 80 ms（p95） | p95 40 / 80 ms，max **220 / 460 ms** |
| 说话人 | 一场内 F0 中位数一致，男女不串 | 已用基频单边否决（`voice.py`） |
| 语速比 | 中文字/秒 ÷ 原句英文音节/秒 = 0.8–1.3 | 未测 |

首尾静音的长尾（max 460 ms）说明 `trim_silence()` 的 −48 dBFS 门限对气声结尾不生效，
落后面的那句会在窗口里"迟到"半秒——听感上是抢话。

## 3 怎么测

三段脚本在 `tools/dub-metrics/`，都只读 job 目录（`$DUB_JOB`，默认 `F:/tmp/s2st/jobs/t5`）：

```bash
PY=/c/Users/Administrator/.workbuddy/binaries/python/envs/default/Scripts/python.exe
DUB_JOB=<job目录> $PY tools/dub-metrics/measure_subtitles_voice.py     # 字幕可读性 + 拟合/合成电平
DUB_JOB=<job目录> $PY tools/dub-metrics/measure_delivered_levels.py    # 交付电平（含 mix gain）、重叠、原声残留
DUB_JOB=<job目录> $PY tools/dub-metrics/measure_truncation_and_residue.py  # 活跃帧电平、截断明细、bed 对照
```

这些脚本原先只活在 `F:/tmp`（不是 git 仓库），和配音链 33 个脚本一样随时会没；
入库的原因不是"以后可能用到"，而是**这套数字每次发版都要重测一遍**，
差 3 dB 听不出来、26 字/秒肉眼只觉得"有点快"，只能靠脚本。

单条命令版本：

```bash
# 整轨响度与真峰
ffmpeg -i out.mp4 -map 0:a -af ebur128=peak=true -f null - 2>&1 | grep -E "I:|Peak:"
# 配音处 vs 无配音处的电平差（原声残留）
#   见脚本 §2，需要 stems_out/{vocals,no_vocals}.wav 与混音成品同时读取
# 字幕阅读速度
#   len(zh) / (cue.end - cue.start)  > 9 即超速
```

**别用截图或肉眼判断这四项**：电平差 3 dB 听不出来但会被审片打回，
字幕 26 字/秒肉眼也只觉得"有点快"。

## 5 缺口

1. **配音成品没有字幕轨**。v3 只有 video + audio 两流（源片也没有字幕流），
   所以今天所有"字幕"讨论的都是 `lines.json` 里的时间轴，观众实际一个字也看不到。
   要在成品里带字幕，得在封装时 `-map` 一条 ASS/SRT，并决定是软字幕还是烧录。
2. **没有可懂度/自然度的客观指标**。MOS 要人听；机器代理（STOI 需要参考信号，本场景没有）也没接。
3. **说话人相似度只能否决，不能打分**。ECAPA 在短句上退化到 0.03–0.17，只能靠基频单边否决，
   所以"这句像不像 Celia"目前无法量化。
4. **分离质量没有量化**。`no_vocals.wav` 里到底残留多少原人声，只有 −0.36 dB 这一个
   全片聚合值；应该按段统计（音乐段 vs 对白段）。
5. **语速比未测**。中文字/秒 与原句英文音节/秒 的比值是"译得是否啰嗦"最直接的指标，
   今天只有 ratio（时长/窗口）这一个间接量。
