# 为什么单一 PSNR 选不出好的引导场（2026-11-05，AMD 后端）

## 触发这件事的那一组数

12 臂引导场实验里，`ab-const-fixed`（每个格子恒为 `(2, 0)`，不含画面的任何信息）在
`real-game-motion` 上同时让三个指标变好、让一个变差：

| 指标 | 变化 | 当时的读法 |
|---|---|---|
| SSIM | +0.0074 | 更好 |
| dE（CIE76） | −0.2205 | 更好 |
| flicker+ | −0.2495 | 更好 |
| PSNR | −0.011 | 更差（被当成噪声） |

一个把运动通道退化成常数的臂不该赢。所以问题不在那个臂，在指标。

## 根因：PSNR 把三个频带的残差混在一起，而低频带占了 97%

把 luma 残差按两个高斯分成三段（σ>4 px / 1–4 px / <1 px），在 `ab-cpu` 参照臂上量
三段的残差能量占比：

| clip | low（σ>4 px） | mid（1–4 px） | high（<1 px） |
|---|---|---|---|
| real-film-cuts | 98.4% | 1.2% | 0.4% |
| real-game-cuts | 96.9% | 2.1% | 1.0% |
| real-game-motion | 98.2% | 1.2% | 0.6% |

三段残差的绝对量级：low 9.4–12.1 级，mid 1.1–1.4 级，high 0.6–0.9 级（8 bit luma）。

**这条 pass 在大尺度上把画面改了 12 个灰阶**——那是 relight/调色，是它存在的理由。
所以 head-line PSNR 量的主要是"改了多少"，不是"改得对不对"。任何中高频上的变化，
在它里面都会被 30–100 倍的低频误差稀释。

最直接的例子就是 `ab-const-fixed` 在 `real-game-motion` 上：

| 量 | 值 |
|---|---|
| mid 带 PSNR | **+1.97 dB** |
| high 带 PSNR | +0.29 dB |
| low 带 PSNR | −0.04 dB |
| **head-line PSNR** | **+0.03 dB** |
| high 带能量比（detail） | **−4.87%** |

中尺度上接近 2 dB 的改善，在 head-line 上只剩 0.03。反过来也一样：一个把细节抹掉
0.3% 的臂，head-line 上看不出代价。**PSNR 不是"没区分度"，是它恰好把一个真实的
trade-off 抵消成了零。**

至于 dE / SSIM / flicker / sigma：它们对"更平滑"都是单向友好的。SSIM 的结构项在模糊下
比 PSNR 宽容得多，dE 只看颜色均值不看结构，flicker 和 sigma 直接就是"帧间/逐像素越稳
越好"。所以四个指标一起变好，只说明一件事：**输出更平滑了**。

## 新加的两个轴

工具在 `tools/benchmark/bands.py`，`analyze.py --bands` 打开，默认关闭（每帧多四次
全分辨率高斯，比循环里其它所有指标加起来还贵）。

1. **分带 PSNR**（`band.bands.{low,mid,high}.psnr`）：残差在各频带的 PSNR。三带分开看，
   一个臂可以"中尺度更好、细纹理更差"而不被平均掉。
2. **detail 比**（`band.detail_ratio_high`）：输出自身的高频能量 ÷ 源的高频能量。
   =1 纹理保住，<1 掉了，>1 是凭空加。这是旧指标集里完全空缺的那一维。
3. **带内相关**（`bands.high.corr`）：区分"变淡"和"变错"。模糊会让能量下降但相关保持；
   场错了会让相关掉。两个臂同样掉 4% 能量，一个 corr 1.00 是软化，一个 corr 0.95 是伪影。

### 刻度：已知退化臂

同一段源上人为造退化，给上面的数字一个标尺（`real-game-cuts`）：

| 人为退化 | detail_ratio_high | 相对 1 |
|---|---|---|
| 无（源） | 1.0000 | — |
| 高斯 σ=0.5 | 0.8556 | −14.4% |
| 高斯 σ=1.0 | 0.5648 | −43.5% |
| 高斯 σ=2.0 | 0.2754 | −72.5% |
| 2× 降采样再升采样 | 0.7546 | −24.5% |

噪声底线：内容应当相同的四个臂（`ab-cpu` / `ab-cpu-x` / `ab-zero` / `ab-neg`）在该
指标上最大散布 0.0006（game-cuts）、0.0011（motion）、0.0001（film）。所以 **0.2% 是
能称为"变化"的下限**。

### 细节丢了是否算损失：先要问"该有多少细节"

最直觉的做法是把输出自己模糊一下再对源打分（overshoot 检验）。第一版只报了 σ=0.75，
全部为负（−0.036 ~ −0.102 dB），当时读成"高频是有效细节，丢掉是真损失"。

**这个读法错了，因为检验本身有拐点，单点会读反。** 频带正交，误差对缩放 k 是抛物线：

```
MSE(k) = (k²·OO − 2k·SO + SS) / px        →        k* = SO / OO = ρ（当 |o|=|s|）
```

`k*` 用每帧两个点积精确算出，不需要扫参数。实测参照臂：

| clip | high detail | high ρ | **high k\*** | mid detail | mid k\* |
|---|---|---|---|---|---|
| real-game-motion | 1.0024 | 0.9270 | **0.9248** | 1.0055 | 0.9756 |
| real-game-cuts | 0.9968 | 0.9012 | **0.9041** | 0.9809 | 0.9971 |
| real-film-cuts | 1.0149 | 0.8495 | **0.8370** | 1.0064 | 0.9568 |

**渲染出来的高频比源"该有的"多约 10%**，因为高频与源只有 ρ≈0.90 的相关，最优幅度就是 ρ
（经典回归收缩）。所以：

- 从 1.00 掉到 0.98 是**朝最优点移动**，不是损失；只有掉过 k\* 才算真丢细节。
- 中频 k\* = 0.96–1.00，本来就在最优点上，所以中频的变化是结构变化、不是幅度问题。
- σ=0.75 已经越过拐点，测到的是"模糊过头"，不是"最后一个百分点值不值钱"。

代价的量级（对输出做 σ=0.5，去掉 14.8–16.0 个百分点高频能量）：整片 PSNR **上升**
0.003–0.005 dB，高频带自己的 PSNR 上升 0.42–0.81 dB。即 **0.0002–0.0003 dB/pp（整片）
或 0.03–0.05 dB/pp（高频带）**。一个掉 2.2% 细节的臂，整片口径下付出 0.0004 dB——
这个数不能当判据用。

## 判决规则

一个带的移动**只有按它占的误差预算折算后才算数**：

```
贡献 = error_share[band] × ΔdB[band]
```

只有 |贡献| ≥ 0.01 dB（8 bit 帧能分辨的下限）才算"这个带动过"。按这个折算，
`real-game-motion` 上 mid **+1.95 dB** 只值 **+0.019 dB**，high +0.22 dB 只值 0.002 dB，
而 low 带（97–99% 预算）几乎就是 head-line 本身。

`bands.verdict()` 的判决：`relight`（只有低频带动，是 relight 变化——不是坏事，低频带正是
这条 pass 的职责，但它和"重建更准"是两个命题）/ `texture-only-gain` / `texture-only-loss`
（高频动了但整片看不见）/ `broad-gain` / `degradation` / `mixed` / `inert`。

另有一条更硬的门槛，用于**引导场类改动**：多数镜头（≥2/3）同号且每段超过 0.05 dB。
整片均值不算数——`real-game-cuts` 上 `ab-cpu-dense` 的 +0.750 里有 +1.65 来自第 1 段
（16 帧），第 3 段是 −0.285，而随机方向的 `ab-noise-dense`(+2.01) 在第 1 段还比它更高。

## 要修的既有结论

1. **"每个臂都在付细节代价"（本文上一版）** —— **收回，量级错了三个数量级。**
   整片口径下 2.2% 的细节值 0.0004 dB，而且 `detail 1.00` 本来就不是最优点（k\*≈0.90），
   掉 2% 是朝最优点移动。细节不能当判据用，只有掉过 k\* 才是损失。
2. **"`ab-cpu-dense`（3×3 补洞）成本≈0 且 PSNR 与 dE 同向，是唯一干净的收益"** —— 仍然收回。
   不是因为细节代价，而是因为它的 +0.750 集中在第 1 段（+1.65），第 3 段 −0.285。
3. **"收益来自场稠密度而非精度"** —— 保留，而且更明确：第 1 段上随机方向的
   `ab-noise-dense`(+2.01) 高于正确方向的 `ab-cpu-dense`(+1.65) 与 `ab-vme`(+0.59)，
   按"场的内容是否正确"排序是反的，按"稠密度/方差"排序才对。
4. **"VME 相对 CPU 场 +0.11/+0.29/+0.18 dB，是收益"** —— 方向仍对但不可用：+0.238
   （game-cuts，集中在第 1 段）/ +0.087（film，4/5 镜头）/ −0.019（motion，前两段为负）。
   唯一"多数镜头一致为正"的臂是 film 上的 VME，而它是全部数据里样本最少的一段。
5. **"多跑几次 repeat 收紧误差棒"** —— 这条做法本身无效：三次 repeat 逐帧哈希完全相同
   （`framemd5` 摘要一致），链路是确定性的，repeat 方差恒为零。方差在镜头之间，不在运行之间。

## 局限

- 频带边界（σ=1、σ=4）是选的，不是推导的。换 1080p 以外的分辨率时，同样的 σ 对应
  不同的像素尺度，需要按分辨率缩放。
- detail 比只覆盖高频。mid 带的"细节"没有等价的无量纲指标，只能看分带 PSNR。
- 只测了三段真实素材，单 pass，`NRNormGovernor=0`。60 fps 队列争用与 gfx1200 未测。
- `k*` 回答"幅度是否过量"，不回答"结构对不对"；它是把输出已知、只缩放该带的前提下的最优值。
- 分段只有 4–5 个，"多数镜头"门槛能排除"全靠一段"，给不出置信区间。
- 整片 PSNR 的绝对量级依赖聚合方式（池化 MSE 28.38 / 逐帧均值 28.71 / 逐帧中位 28.51），
  换口径符号不变但 Δ 的量级会差近一倍。
